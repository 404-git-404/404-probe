## Post-review correction and redeployment

Independent review after the first real-host run found that Go's default `[]uint8` JSON decoding accepts `null` array elements as NUL bytes. The source was tightened to accept journald byte arrays only when every element is a lexical base-10 integer in the inclusive range 0–255. Regression coverage includes `[null]`, `[65,null,66]`, out-of-range input, and a valid UTF-8/ANSI byte-array message. The focused tests, full `internal/securitycollector` package, all-package suite excluding only the archive-without-Git metadata fixture, and `go vet` passed locally.

The correction was committed as `31913c02c580297c48e8a24fcb5a3921af7f4fbc`, rebuilt with `vcs.modified=false`, and deployed to the Server and both Agents. On the Debian test Server, the exact source archive passed:

- `go test ./internal/securitycollector -count=1` — exit 0
- `go test -race -p=1 ./internal/securitycollector -count=1` — exit 0
- `go test ./... -count=1 -skip TestInspectCandidateBuildReadsGoExecutable` — exit 0
- `go vet ./...` — exit 0

After deployment, real incremental journal collection was run twice on each Agent. The first run was complete and parsed 916 lines/events on Agent 8168 and 69 lines/events on Agent 8260. The immediately following run was complete with zero lines/events on both, confirming checkpoint advancement without replay. Final exports were readable but not writable by the Agent account; private checkpoints remained unreadable. Server/Agent/updater/security timer/sing-box service state and endpoints were rechecked healthy. The Server's sing-box remained intentionally inactive, while both Agent Clash APIs returned 200. Agent 8260's aggregate sing-box configuration hash remained unchanged from the earlier uninstall/restore baseline.
