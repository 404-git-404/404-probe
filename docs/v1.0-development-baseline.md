## 3. 协议、字段和迁移计划

迁移只前进、不在运行中降级。正常 Server 升级沿用受保护数据库备份、迁移、健康检查和故障回滚；显式卸载的数据删除语义不得进入升级路径。

| 计划 schema | 数据 | 用途与约束 |
| --- | --- | --- |
| 15 | `agent_traffic_baselines(agent_id PRIMARY KEY, rx_total, tx_total, started_at, request_id)` | 累计显示起点。事务读取当前永久累计并写基线；`request_id` 使重复请求幂等。 |
| 16 | `agent_removal_operations`、短期回执凭据哈希/过期时间及状态事件 | 远端永久删除状态机。状态只能单向推进；最终业务清理由事务完成；最小审计回执与 Agent 业务历史分离。 |
| 17 | Agent 可选管理能力/单次国家识别请求状态（如最终实现不需持久化，可合并进 removal/control 表并保持 schema 16） | Server 只向声明能力的 v1 Agent 下发；旧 Agent 显示升级要求。 |

协议新增字段全部采用可选/零值兼容：

- report：`network_families`（已确认的 `ipv4`/`ipv6`）、远端卸载与单次国家识别 capability；不在 report 中传可执行命令。
- Web Agent detail：累计显示值及 `traffic_started_at`、网络族、删除操作状态、管理能力。
- control：使用固定枚举操作，不提供任意 shell。远端卸载使用专用操作和仅能提交该操作回执的短期 bearer 凭据。

Server 的 report 解码当前使用 `DisallowUnknownFields`。因此 v1 Agent 发送新增字段给 v0.9.3 Server 会失败，正式升级顺序固定为 **Server 先、Agent 后**。v1 Server 必须继续接受 v0.9.3 Agent 缺失上述字段，并将功能显示为“不支持/需升级”，不能把缺失值解释为失败或清理完成。

| Server | Agent | 遥测/历史 | v1 管理能力 | 支持结论 |
| --- | --- | --- | --- | --- |
| v1.0 | v1.0 | 完整 | 完整 | 目标组合。 |
| v1.0 | v0.9.3 | 保持现有 report、Job、Selector、升级与安全数据 | 网络族、重新识别、远端永久删除显示“升级 Agent 后可用” | 支持分批升级。 |
| v1.0 | v0.9.0-v0.9.2 | 保持这些版本原有的已协商能力 | 同上；不得下发未知操作 | T13 在隔离 Debian 实测后确定最早支持点。 |
| v0.9.3 | v1.0 | 新 report 字段会被严格解码拒绝 | 不可用 | 不支持；安装/升级流程必须阻止 Agent 先升级。 |
| v0.8.x 或更早 Server | v1.0 | 未承诺 | 不可用 | 不支持；先升级 Server。 |

Agent 分批升级期间，v1 Server 不撤销旧 Agent 凭据、不重写稳定 ID、不覆盖用户名称和国家手动覆盖。数据库新增列/表不得改变旧字段含义。正常回滚只能在迁移兼容边界内使用现有受保护备份恢复 Server 二进制和数据库；不尝试让旧二进制打开更高 schema。

- `/usr/local/sbin/404-probe-install`

## 6. 固定产品语义

- **V4/V6**：表示非 loopback、接口为 up、地址不是 unspecified/multicast，且 IPv6 不是 link-local 的本机接口地址族存在。IPv4 私网地址有效；容器/隧道/虚拟接口只要处于 up 且有符合条件的地址也有效。本字段不声称公网可达，不持续探测外网。
- **名称**：`agents.name` 是用户名称，稳定 ID 为 `agents.id`，主机名只属于最新 telemetry；report 永不更新用户名称。
- **国家/地区**：安装时一次自动识别；手动覆盖优先且不会被自动结果替换。主动“从 Agent 重新获取”每次只触发一次，失败保留旧值。
- **累计重置**：只改变展示基线；周期流量、原始计数、永久累计序列和历史均不变。
- **永久删除**：不是现有 revoke。操作进入状态机后先阻止新任务并处理升级冲突，最终只在收到受验证的清理回执后显示完成；失联停在等待/待确认。
- **本地卸载**：是显式破坏性动作且不提供保留数据分支。旧版无确认的 `uninstall` 命令不能静默变成删数据，必须要求新的显式确认或非交互确认参数。
